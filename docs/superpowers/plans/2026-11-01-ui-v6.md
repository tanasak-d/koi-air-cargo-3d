# แผนงาน UI V6 (หน้าติดตามพัสดุ โทนดำขาว ปรับตามขนาดจอ)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** เปลี่ยนหน้าเว็บ `Koi_Air_Cargo_3D.html` ให้ตรงกับร่าง `mockup/ร่าง_UI_V6.html` ที่มาร์ชอนุมัติ (หน้าต้อนรับ · แถบเส้นทาง 6 สถานี · การ์ดข้อมูลแบบไอคอน · โหมดนำเสนอ · มือถือภาพเต็มจอ + แผ่นข้อมูลลากขึ้น) และจัดหน้าตามขนาดจอเอง แล้วส่งออก V6

**Architecture:** ยังเป็น HTML ไฟล์เดียวเหมือนเดิม แก้ 3 ส่วน: CSS ใน `<style>`, โครงหน้าใน `<body>`, และบล็อก `koi-ui` ฟังก์ชัน `render*` ใหม่ทุกตัวเป็นฟังก์ชันบริสุทธิ์ (รับ state คืนสตริง HTML) จึงทดสอบใน Node ได้ด้วย `loadBlocks` ส่วน `mount()` เป็นตัวเอา HTML ไปใส่หน้าเว็บ ฉาก 3 มิติ (`koi-scene`) ไม่ต้องแก้ เพราะปรับขนาดตามกล่องแม่ด้วย `ResizeObserver` อยู่แล้ว

**Tech Stack:** HTML/CSS/JS ล้วน (ES5 แบบเดิมในบล็อก koi-ui), Three.js r128 ที่ฝังไว้, node:test

**Spec:** `mockup/ร่าง_UI_V6.html` (ร่างโทนดำขาว ที่มาร์ชตอบ "ผ่าน" เมื่อ 1 พ.ย. 2026) + บรีฟของมาร์ช: สไตล์หน้าติดตามพัสดุแบบมืออาชีพ · จอหลักคือโปรเจกเตอร์และแล็ปท็อป · มือถือภาพเต็มจอ + แผ่นข้อมูลลากขึ้น · พื้นขาว ตัวหนังสือดำ สีเขียว/เหลือง/แดงเฉพาะสถานะ

## Global Constraints

- ไฟล์ส่งออกไม่เกิน 5 MB และไม่อ้างทรัพยากรภายนอก (ทำงานออฟไลน์ได้) — เทสต์ใน `tests/scaffold.test.mjs` ต้องผ่านต่อ
- โทนสีธีมสว่าง: `--bg:#f2f2f2` `--surface:#ffffff` `--text:#111111` ปุ่มหลัก/ผ่านแล้ว/ตอนนี้ = `#111111` · สีสถานะคงเดิม `--ok:#11743a` `--warn:#8a5300` `--bad:#b3261e`
- ธีมมืดยังสลับได้: พื้นดำ ตัวหนังสือขาว ตัวเน้น = `#f2f2f2` บนพื้นดำ
- ทุกคู่สีตัวอักษรผ่าน WCAG AA (≥ 4.5:1) ทั้งสองธีม
- สถานะต้องมีไอคอนหรือข้อความคู่กับสีเสมอ (✓ ✕ ● ⚠ หรือคำ) ห้ามบอกด้วยสีอย่างเดียว
- "ตอนนี้" ต้องแยกจาก "ผ่านแล้ว" ได้โดยไม่ใช้สี: ผ่านแล้ว = วงดำเต็ม · ตอนนี้ = วงดำมีวงรอบ 2 ชั้น + ป้ายคำว่า "ตอนนี้"
- ปุ่มที่กดด้วยนิ้วสูงอย่างน้อย 44px บนมือถือ · ไม่มีการเลื่อนแนวนอนที่ความกว้าง 360px ขึ้นไป
- ทุกอย่างที่ลากได้ต้องมีปุ่มกดแทน (แผ่นข้อมูลมือถือ) และใช้คีย์บอร์ดได้
- เคารพ `prefers-reduced-motion`: ไม่มีอนิเมชันเลื่อนแผ่น/จางภาพเมื่อผู้ใช้ปิดการเคลื่อนไหว
- ข้อความจากข้อมูลทุกตัวผ่าน `esc()` หรือ `renderGlossary()`
- คีย์ลัดเดิมใช้ได้ครบ: ← → · Space · P · T · O · Esc เพิ่ม Enter = เริ่มจากหน้าต้อนรับ
- คอมเมนต์โค้ดเป็นภาษาไทยแบบง่าย
- commit ด้วย `git -c user.name=Marc -c user.email=<อีเมลของมาร์ช>` ท้ายข้อความใส่ `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` · ทำบนสาขา `feat/ui-v6` ห้ามรวมเข้า main หรือ push จนกว่ามาร์ชสั่ง

## คำถามที่ต้องให้มาร์ชตอบก่อนลงมือ

ร่างไม่ได้บอกเรื่องเหล่านี้ นะนายใส่ค่าที่แนะนำไว้ในแผนแล้ว ถ้ามาร์ชเลือกอื่น นะนายจะแก้แผนก่อนเริ่ม

1. **เนื้อหาแท็บเดิมที่ร่างไม่มี** (ทำไมสำคัญ · ถ้าผ่าน/ไม่ผ่าน · 4-Flow) — แนะนำ: เก็บไว้ในหัวข้อพับได้ "ดูเพิ่มเติม" ใต้การ์ดข้อมูล (Task 3)
2. **ข้อความ "ทำอะไร" ในการ์ด** ร่างใช้ข้อความสั้น แต่ข้อมูลจริงยาว 1–2 ประโยค — แนะนำ: ใช้ข้อความเต็มจากข้อมูลเดิม ไม่แก้ข้อมูล (การ์ดตัดบรรทัดเอง)
3. **ชื่อสถานีในแถบเส้นทาง** ร่างใช้ "ฟาร์มผู้ส่ง · นาริตะ NRT · เที่ยวบิน JL707 · สุวรรณภูมิ BKK · ด่าน DOF · กักกัน · ฟาร์มบริษัท" ส่วนข้อมูลเดิมมี `short` = "ผู้ส่ง · NRT · เครื่องบิน · BKK · DOF · ผู้รับ" — แนะนำ: เพิ่มช่อง `label` ใน `STATIONS` ตามชื่อในร่าง (Task 2)
4. **หน้าต้อนรับ** — แนะนำ: แสดงทุกครั้งที่เปิดเว็บ ถ้าเปิดลิงก์ที่มี `#step=N` ให้ข้ามหน้าต้อนรับ (Task 5)
